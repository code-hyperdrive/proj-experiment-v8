2b. Sign in with Google

This is a real full-page redirect to Google's consent screen — can't be done via fetch()/AJAX. Requires GOOGLE_CLIENT_ID / GOOGLE_CLIENT_SECRET to be real values (see backend/wrangler.toml and backend/.dev.vars) — until then this will reach Google but fail with an "invalid_client" style error, which is expected, not a bug here. After a successful sign-in, Google redirects back to /auth/google/callback, which currently just renders raw JSON in the browser (no frontend wiring exists yet to receive it — see that route's own code comment).
